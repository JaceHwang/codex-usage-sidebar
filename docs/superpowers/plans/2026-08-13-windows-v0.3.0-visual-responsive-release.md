# Codex Usage Sidebar v0.3.0 Visual and Responsive Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Correct the five reported Windows UI issues, validate responsive placement on the real Windows 11 x64 Codex client, and produce provenance-bound v0.3.0 Windows x64 and macOS arm64 release assets.

**Architecture:** Platform-neutral countdown, spectrum, and placement policies live in `CodexUsageSidebar.Core`; build-gated UIA extraction and WPF rendering live in `CodexUsageSidebar.Windows`. After the beta device UI passes its focused checks, the exact `v0.3.0` branch receives a version-only promotion. The complete release matrix validates that promoted source commit. A later packaging commit may add only the validation evidence; both platform workflows then build the validated source commit and record both identities.

**Tech Stack:** .NET 8, WPF, Windows UI Automation, MSTest, PowerShell 5.1/7, Swift 6/AppKit, GitHub Actions, Bash/Python provenance verifiers.

## Global Constraints

- Windows support is Windows 11 AMD64/x64 build 22000 or newer; Windows ARM64 is out of scope.
- Unknown, incomplete, ambiguous, or changed UIA structures hide the overlay; no guessed coordinates.
- The overlay remains external, no-activate, per-user, and does not modify the Codex package.
- Existing v0.2.3 assets and release files are never overwritten or re-uploaded.
- The branch requested for promotion is exactly `v0.3.0`.
- Windows setup publication remains blocked until the complete real-device matrix passes.
- macOS is rebuilt as arm64 v0.3.0 without changing the approved visual behavior.

## Validated source and packaging commit

Release evidence cannot contain the Git SHA of the commit that first adds that evidence, because
that would be self-referential. The release therefore uses two immutable identities:

- `validatedSourceCommit`: the exact promoted v0.3.0 source tested on the Windows device;
- `packagingCommit`: a descendant that may differ only by
  `docs/validation/windows-v0.3.0.json`.

Windows x64 and macOS arm64 assets are built from `validatedSourceCommit`. Provenance also records
`packagingCommit` and the GitHub Actions artifact identity. Any other post-validation source change
invalidates the matrix and requires a new validated source commit.
