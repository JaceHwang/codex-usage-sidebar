# Windows v0.3.0-beta.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and verify every Windows beta component that does not require a live Windows Codex session, while preserving macOS v0.2.3 and making real-device UIA/visual validation an explicit release gate.

**Architecture:** Keep the macOS Swift package under `native`, add a .NET 8 solution under `windows`, and share sanitized JSON contract fixtures. A platform-neutral C# core drives models and state. Thin WPF/Win32/UIA, control, and installer layers consume interfaces so orchestration is testable offline. CI produces only a candidate artifact; publishing remains blocked until the Windows device matrix passes.

**Tech Stack:** .NET 8, C# 12, WPF, Windows UI Automation, Win32 P/Invoke, System.Text.Json, MSTest, Swift 6, Bash/PowerShell, GitHub Actions.

## Constraints

- Work on `codex/v0.3.0-beta.1`, based on the latest `origin/main`.
- Do not change, overwrite, or republish v0.2.3 release assets.
- Do not claim Windows usability without the real-device gate in the design.
- Never modify official Codex application files or bypass OAuth/OS security.
- Use exact argument arrays and per-user paths; no shell interpolation of user-controlled data.
- All new behavior starts with a failing automated test.

## Completion boundary

This plan is complete on macOS when all offline tasks and regression gates pass and the branch
contains a reproducible Windows candidate pipeline. It does **not** authorize a GitHub prerelease.
The Windows installer becomes releasable only after the design's real-Windows gate is executed,
recorded, reviewed, and merged into the same source/provenance chain.
