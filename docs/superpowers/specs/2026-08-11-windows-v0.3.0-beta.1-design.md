# Codex Usage Sidebar Windows v0.3.0-beta.1 Design

## Context

Codex Usage Sidebar v0.2.3 is a macOS implementation. Its quota source—the official Codex
`app-server` JSON-RPC interface—is portable, but window discovery, title-bar placement, overlay
rendering, process lifecycle, permissions, and packaging are AppKit/Accessibility-specific. The
Windows beta will keep the data and interaction semantics while replacing only the platform layer.

This phase deliberately implements everything that can be proved without a Windows Codex desktop
session. UI Automation selectors, title-bar geometry, DPI behavior, visual parity, and the final
installer payload remain release gates that must be exercised against a signed-in Windows Codex
client before any Windows asset is described as usable.

## Approved visual decision brief

The approved macOS v0.2.3 interface is the visual and interaction source of truth for Windows.
No separate Windows redesign or additional mockup round is required. The Windows implementation
must preserve the same information hierarchy, density, color semantics, and interaction model while
using native Windows rendering mechanics where the operating system requires them.

### Product feel

- restrained, native, trustworthy, and efficient;
- visually integrated with the Codex title bar rather than presented as a separate utility;
- equal behavior and content across macOS and Windows wherever platform APIs allow it.

### Compact control

- one-line remaining percentage plus reset time, with the percentage emphasized;
- 13–14 point system typography, semibold/bold hierarchy, and theme-aware label color;
- transparent host-like background at rest and a subtle 7% neutral hover/pinned surface;
- the same continuous quota color scale: green at 100%, orange at 49%, red at 10%, with a deeper
  critical red below 10%;
- hover opens the detail card, click pins it, and a second click closes it without activating or
  stealing keyboard focus from Codex.

### Detail card

- 300 logical-pixel reference width, 12 logical-pixel continuous-looking corner radius, subtle
  separator-color border and native shadow;
- title and compact blue outlined version badge on the left, live percentage on the right;
- 4 logical-pixel quota spectrum bar and a restrained divider before the detail rows;
- two-column rows for plan, period, reset, Credits, and every Bank entry; long values wrap without
  truncating required dates;
- countdown digits use larger semibold typography and the live quota accent, while units and
  punctuation remain smaller and quieter;
- Simplified Chinese, Traditional Chinese, and English copy matches the macOS information model.

### Windows-only adaptation boundary

Windows may use Segoe UI, per-monitor DPI-aware logical units, native focus cues for installer
controls, and Windows shadow/contrast behavior. These are compatibility adaptations, not permission
to change content order, interaction, quota colors, spacing rhythm, or product personality. The
overlay remains non-activating; keyboard and screen-reader behavior must be verified without hiding
or consuming Codex controls. Light, dark, high-contrast, 100/125/150/200% scaling, and multi-monitor
results are release gates.

## Goals

- Establish a monorepo layout that keeps the released macOS implementation intact and adds an
  independently buildable Windows implementation.
- Share versioned rate-limit fixtures and behavioral contracts across platforms.
- Implement and test the Windows-neutral quota model, decoding, localization, relative-time
  formatting, color scale, interaction state, refresh policy, and anchor/collision calculations.
- Define thin Windows interfaces for Codex process/window discovery, UI Automation snapshots,
  overlay presentation, autostart, and installation so their orchestration can be tested with fakes.
- Provide a diagnostic probe and Windows CI/build/package validation that can be run on the future
  Windows test machine without redesigning the project.
- Preserve macOS v0.2.3 behavior throughout beta development.

## Non-goals for the offline phase

- Claiming that a UI Automation selector works before inspecting the real Windows Codex tree.
- Publishing a Windows installer before real-device UI, lifecycle, accessibility, DPI, light/dark,
  sidebar, and upgrade testing passes.
- Modifying, injecting into, or replacing files inside the official Codex installation.
- Rewriting the stable macOS code in C# or changing the existing v0.2.3 release assets.
- Bundling an unverified `codex.exe`; the final payload must record its authoritative source and SHA.

## Architecture

### Shared contracts

Checked-in, sanitized JSON fixtures describe app-server rate-limit responses and notifications.
Placement fixtures describe available title-bar rectangles and expected anchor decisions. Both
Swift and C# tests consume the same inputs, preventing platform drift without forcing a shared
runtime language.

### Portable Windows core

`CodexUsageSidebar.Core` targets `net8.0` and has no WPF, Win32, or UI Automation dependency. It
owns immutable quota models, `System.Text.Json` decoding, locale selection, compact duration
formatting, gradient colors, hover/pin state, refresh scheduling, and geometry decisions. The data
transport is an interface over newline-delimited JSON-RPC so tests can replay app-server messages.

### Windows platform host

`CodexUsageSidebar.Windows` targets `net8.0-windows` with WPF. Presentation and orchestration depend
on interfaces for process discovery, window snapshots, UI Automation scanning, overlay surfaces,
DPI conversion, and autostart. Win32/UIA implementations are isolated behind those interfaces.
The future real-device pass will bind selectors to semantic controls and measured rectangles; it
will not depend on screen coordinates captured on one machine.

The overlay is a separate transparent, non-activating, topmost WPF window owned logically by the
Codex window. It renders the compact button and popup, supports click-to-pin plus hover, follows
theme and DPI, and re-resolves placement whenever host geometry changes. It never writes into or
injects code into Codex.

### Control and lifecycle

`CodexUsageSidebar.Control` supplies idempotent `ensure`, `status`, `repair`, `stop`, `uninstall`,
and `probe` commands. A per-user singleton, atomic state file, verified executable path, bounded
process operations, and sanitized diagnostics mirror the safety properties of the Mac companion.
The plugin hook eventually uses `commandWindows` to invoke the packaged control executable.

### Installer

The Windows installer is a self-contained .NET desktop manager rather than an MSI that needs admin
rights. It installs only under `%LOCALAPPDATA%\CodexUsageSidebar`, registers per-user autostart,
copies the exact versioned plugin payload, guides Codex authorization, verifies runtime health, and
supports repair/uninstall. Packaging produces:

```text
codex-usage-sidebar-v0.3.0-beta.1-windows-x64-setup.exe
SHA256SUMS.txt
WINDOWS-PROVENANCE.json
```

The setup asset is not publishable until the real Windows gate passes and provenance binds the
tested Codex runtime, source commit, architecture, SDK, executable digests, and signing state.

## Version policy

The development line and Windows assemblies use `0.3.0-beta.1`. The stable plugin manifest and Mac
release remain v0.2.3 until an integration milestone builds and verifies matching beta payloads.
No v0.2.3 GitHub asset is overwritten. A later beta promotion updates the unified manifest once,
adds a cache-buster, rebuilds both platform payloads, and publishes a prerelease.

## Offline verification gate

The current Mac can prove shared fixtures, portable .NET tests, cross-target compilation, packaging
input rejection, deterministic names/checksums/provenance, repository validation, and all existing
Swift regressions. Windows CI additionally proves native compilation and installer assembly.

## Required real-Windows gate

Before publication, a Windows 11 AMD64 test matrix (named `x64` by the .NET and packaging toolchain)
with the current signed-in Codex desktop must
capture the process/window/UIA tree and verify: expanded/collapsed sidebars, narrow/wide windows,
right-panel resizing, multiple monitors, 100/125/150/200% DPI, light/dark/system themes, three
languages, hover/pin behavior, focus/non-activation, sleep/resume, Codex restart/upgrade, install,
repair, uninstall, and app-server authorization. The resulting selectors and screenshots become
versioned fixtures. Failure of any placement or overlap case blocks the installer asset.

Windows ARM64 is outside the scope of v0.3.0-beta.1. It is not built, tested, packaged, or required
by this version's release gate.

## Upgrade resilience

Discovery prefers stable process identity, window ownership, semantic UIA properties, and relative
geometry. Selector sets are versioned and diagnostics report unknown trees without guessing. The
control command is idempotent, hooks merely request `ensure`, and the installer can repair the
per-user payload. This keeps Codex upgrades recoverable with one action while retaining an explicit
compatibility gate for major UI changes.
